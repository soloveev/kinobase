# Форма справочной карточки

Карточка — справочная часть тайтла: как он называется, когда вышел, кто его сделал, о чём он в двух абзацах и какими тегами описывается. Материалы агента — «Зачем смотреть» и «После просмотра» — в карточку не входят: их форма в [DOSSIER-FORMAT.md](DOSSIER-FORMAT.md).

Где искать — в [SOURCING.md](SOURCING.md). Как проверять — в [VERIFICATION.md](VERIFICATION.md). Что законно писать в аннотации — в [LEGAL.md](LEGAL.md).

Аннотация — тоже текст, который читает пользователь, и **общие правила письма живут в [DOSSIER-FORMAT.md](DOSSIER-FORMAT.md)**: человек при первом упоминании несёт свою роль, атрибуция — издание в скобках со ссылкой и ничего сверх, оговорок о том, чего не следует, в тексте нет.

Карточка отличается от досье природой работы: здесь нет интерпретации, здесь сверка. Почти всё проверяется по двум независимым базам, и почти на всё есть однозначный ответ. Поэтому главное правило короткое: **не нашли — оставляем пусто**. Пустое поле честно, догадка — нет.

Отсюда и послабление в чтении. Досье пишется по полным текстам страниц, потому что там важны формулировка и оговорка; справочное поле — это одно значение, и **сходящиеся выдержки из нескольких независимых источников для него достаточное основание**. Читать страницу целиком нужно там, где значение спорное: разные базы называют разных людей, дата переносилась, роль в титрах неоднозначна.

## Поля

Данные лежат в `content/films-data.json`, схема — в `src/db/schema.ts`.

| Поле | Обязательно | Что это |
|---|---|---|
| `titleRu` | да | Русское название. Год в него **не пишется никогда** |
| `titleOriginal` | да | Оригинальное название. Ключ, по которому тайтл ищут все скрипты наполнения |
| `posterPath` | да | `/posters/<slug>.jpg`; файл кладётся в двух размерах |
| `releaseDate` | да, если известна | `ГГГГ-ММ-ДД`; **дата мирового проката**, не премьеры и не спецпоказа. У объявленного, но не вышедшего — объявленная дата |
| `imdbId` | да, если есть | `tt` и цифры |
| `imdbRating` | нет | Число с одним знаком после запятой |
| `kinopoiskId` | да, если есть | Числовой идентификатор |
| `kinopoiskRating` | нет | Число с одним знаком после запятой |
| `annotation` | да | Один-два абзаца связного текста |
| `director` | да | Кириллицей |
| `producer` | нет | Кириллицей. Ведущие продюсеры через запятую, а не весь список сопродюсеров: карточка не заменяет титры |
| `screenwriter` | нет | Кириллицей |
| `composer` | нет | Кириллицей |
| `soundDesigner` | нет | Кириллицей |
| `cast` | да | Массив имён кириллицей, ключевые роли, а не весь состав |
| `tags` | да | По словарю `src/lib/tags.ts` |
| `seasonsReleased` | у сериала | Целое не меньше единицы |
| `nextSeasonNumber` | нет | Целое; пусто — продолжения не ждём |
| `nextSeasonDate` | нет | `ГГГГ-ММ` или `ГГГГ-ММ-ДД` |
| `createdAt` | да | `ГГГГ-ММ-ДД`, день, когда тайтл заводят в базу. Ставится один раз и задним числом не меняется |
| `watched`, `wantToWatch` | нет | **Личные поля. Агент их не проставляет** — их ставит владелец |

Личные поля — оценка, звёздочка вкуса, комментарий, обе отметки — самое ценное в базе. Скрипты наполнения их не трогают, и агент, заводящий карточку, тоже.

## Дата заведения

`createdAt` — сегодняшний день на момент, когда карточка заводится, и записывается он сразу, вместе с остальными полями. Это не факт о фильме, а отметка о собственном действии базы: по ней видно, что заведено раньше, что позже, и какие тайтлы ждут материалов дольше всех.

Дата принадлежит тайтлу, а не базе, в которой он лежит. Поэтому её нельзя проставлять прогоном скрипта: долив на сервер случается позже локального, и «сегодня» развело бы боевую базу с локальной копией на несколько дней. Дата едет из файла данных, и обе базы получают одну и ту же. Записи без даты `add-films` и `seed` отклоняют до открытия базы, а `npm run check-data` называет её кодом `no-created-at`.

Заведённую дату не переписывают: `refresh-films` её не переносит, и правка задним числом означала бы, что история заведения потеряна. Пустой она остаётся только у тайтлов старше самой колонки, которых не нашлось в истории файла данных.

## Название

`titleOriginal` обязателен и служит ключом: по нему тайтл ищут `add-films`, `tag-films`, `fill-seasons`, `fill-dossiers` и `fill-people`. Русское название ключом быть не может — одноимённые тайтлы существуют: «Призрак в доспехах» 1995 года и одноимённый сериал 2026-го это два разных произведения, и словарь по русскому названию молча оставил бы от них одно.

Год в `titleRu` **не пишется никогда**, даже когда название неоднозначно. Неоднозначность разрешается при показе: страница сама приписывает год, если название встречается в базе больше одного раза. Написанный в данные год сломал бы поиск по названию.

**Русское название берётся с Кинопоиска — это решение принято, и спрашивать о нём владельца не надо.** Владелец называет тайтл на слух и по памяти, и его вариант регулярно расходится с прокатным: «Плюрибус» вместо «Одна из многих», «Больница Питт» вместо «Питт», «Побочные явления» вместо «Частые побочные явления». В `titleRu` идёт прокатное название, потому что туда же ведёт ссылка из карточки и так тайтл называет русская пресса. Правило решено владельцем 24 августа 2026 года.

## Аннотация

**Аннотация — короткий пересказ завязки, и больше в ней ничего нет.** Один абзац, ориентир 200–500 знаков. Ровно то, что стоит под постером на Кинопоиске или в строке описания на IMDb: кто герой, что с ним случилось, во что он из-за этого ввязался.

**Источник обязателен и он один из двух: Кинопоиск или IMDb.** Своё описание сюжета не сочиняется. С Кинопоиска текст берётся по-русски и правится по языку; с IMDb — переводится на русский, потому что сайт русскоязычный, и правится так же. Из какого именно источника взята аннотация, записывается строкой в таблицу фактов журнала наравне с прочими полями: это проверяемый факт, а не свободный текст. Не нашли описания ни там, ни там — ищем русскую прокатную аннотацию дистрибьютора, а не пишем сами.

Что **не идёт** в аннотацию — правило от 31.08.2026, решение владельца:

- **дата выхода, премьера, прокат, площадка, порядок показа серий.** Это отдельные поля карточки и строки страницы; в аннотации они дублируются и вытесняют собственно сюжет;
- **производственная рамка**: студия, страна, компания-производитель, бюджет;
- **имена создателей и исполнителей** — режиссёр, сценарист, продюсеры, состав. Все они уже стоят в своих полях карточки, и повторять их прозой незачем;
- **литературная основа и место в франшизе** — «экранизация романа такого-то», «приквел такого-то сериала». Об этом говорит досье, а не справка;
- **награды, номинации, фестивальная судьба, цифры сборов**;
- спойлеры, пересказ второй половины сюжета, маркетинговые восклицания («захватывающий», «долгожданный»), оценка качества («признание критиков», «современная классика»).

Прежняя формулировка требовала обратного — ~~«имена ключевых создателей и исполнителей, производственная рамка (студия, платформа, страна), обстоятельства выхода — дата, площадка, порядок показа серий»~~ — и отменена 31.08.2026: на живом материале она разрослась до полутора тысяч знаков производственной справки, в которой завязка терялась. Пометка оставлена намеренно, чтобы правка не читалась регрессией.

Правило действует и на **сериал**: аннотация описывает завязку сериала, а не расписание сезонов. Сколько сезонов вышло и когда ждать следующий — поля `seasonsReleased`, `nextSeasonNumber`, `nextSeasonDate`.

**Правило источника старше ориентира длины.** У невышедшего тайтла Кинопоиск и IMDb часто держат только логлайн в 100–170 знаков, и до 200 его не дотянуть, не сочиняя. Берётся то, что есть, дословно и без дописывания; длина подрастёт, когда источник заведёт описание. Заход 15.09.2026: так решили все пять агентов независимо — «Маск», «Прайм-тайм», «Диггер», «Чернила», «Ночь дурака».

Аннотация — публикация, поэтому [LEGAL.md](LEGAL.md) действует и на неё.

## Идентификаторы

Опознать тайтл однозначно важнее, чем быстро: одноимённых много, ремейков ещё больше. Сверять надо по году **и** режиссёру, а не по названию.

- **TMDB** — рабочий ключ, с него удобно начинать: `https://www.themoviedb.org/search?query=<название>` даёт числовой идентификатор в ссылках вида `/movie/701387-bugonia`. В базу TMDB-идентификатор не пишется, он нужен для постера.
- **IMDb** — идентификатор вида `tt12300742`. Страницы IMDb роботам не отдаются; работает поисковая подсказка `v2.sg.media-imdb.com/suggestion`.
- **Кинопоиск** — числовой идентификатор из адреса карточки. Сайт часто отвечает капчей; тогда идентификатор берётся из выдачи поиска или зеркал, а рейтинг, если его не видно, остаётся пустым.

Рейтинги — величина изменчивая, и это нормально: они снимаются на дату заведения карточки и не считаются фактом навсегда.

**Счёт критиков Кинопоиска в `kinopoiskRating` не идёт.** У невышедшего фильма на странице стоит только оценка кинокритиков (в процентах и баллах); это другая величина, и поле остаётся пустым до появления зрительского рейтинга. Заход 15.09.2026, «Чернила»: агент записал критические 7,4, координатор обнулил.

**Если тайтл однозначно опознать не удалось — спросить владельца, а не выбирать.** Неверный идентификатор уводит ссылку в карточке на чужой фильм, и заметить это трудно.

## Имена создателей

Кириллицей, по правилам из [SOURCING.md](SOURCING.md). Латиница в этих полях означает, что запись не доделана.

**Кинопоиск для имён — первый источник, а не безусловный.** Его собственные поля бывают ошибочны: у «Железобетона» в графе «Сценарий» стоял режиссёр пилота 1999 года вместо сценариста, и поймано это было сверкой с IMDb и Википедией (15.09.2026). Имя берётся с Кинопоиска, когда независимые базы с ним сходятся; расходятся — решает содержание титров, а не ранг источника.

Состав исполнителей — ключевые роли, а не полный список: карточка не заменяет титры.

### Поле `director` у сериала называет постановщиков, а не создателя

Решение владельца 28.08.2026. До него поле у сериала несло создателя и шоураннера, и на трёх тайтлах подряд это оказалось прямой неправдой: в «Андоре» стоял Тони Гилрой, не снявший ни одной из двадцати четырёх серий, в «Извне» — Джон Гриффин, не снявший ни одной из сорока. Расхождение нашли независимо четыре зоны поиска, и каждая завела его как ошибку справки — то есть поле читалось как «кто стоял за камерой» не только машиной, но и всяким, кто открывал титры.

Поэтому: **`director` — постановщики по титрам, в порядке убывания числа снятых серий.** Создатель, шоураннер и автор замысла живут в `screenwriter`, где они обычно и стоят верно.

**Порог участия — десятая часть серий тайтла.** Без него у длинного сериала поле превращается в список из трёх десятков имён, а с ним оно остаётся проверяемым и не требует суждения. У «Извне» из шести постановщиков в поле попали четверо: Бендер с двадцатью тремя сериями из сорока, Ла Рош с шестью, Ренфро и Тёрнер с четырьмя; двое снявших по две серии — нет. У «Андора» с его блочным устройством порог проходят все шестеро.

Правило действует и на фильм, где оно ничего не меняет: постановщик там один и он же обычно автор.

Два уточнения с захода 15.09.2026, где правило впервые встретилось с длинными сериалами. **Порог читается как «не меньше»**: у «Твин Пикса» 48 серий дают порог 4,8, и постановщик с четырьмя сериями не проходит, а Линч с двадцатью четырьмя — единственный, кто проходит, хотя Кинопоиск в шапке называет троих. **Разбивку по сериям ни TMDB, ни Кинопоиск не отдают** — TMDB показывает лишь суммарное число серий на человека; когда и этого нет, считать по таблице эпизодов английской Википедии (`List_of_..._episodes`).

## Теги

Словарь `src/lib/tags.ts` — источник правды: тег вне словаря записать нельзя, скрипт отвергнет весь файл. Четыре категории: форма (`film` или `series`), вид (`live-action`, `animation`, `documentary`), жанры и настроение.

По одному тегу формы и вида обязательно; жанров и настроений — сколько есть по существу, но набор целиком остаётся обозримым.

**Теги пишутся одновременно в два файла** — `content/films-data.json` и `content/tags-data.json`. Правка одного молча откатывается скриптом наполнения; расхождение ловит `npm run check-data`.

## Сезоны сериала

Три поля, они заполняются только у тайтла с тегом `series`.

| Поле | Смысл |
|---|---|
| `seasonsReleased` | Сколько сезонов уже вышло |
| `nextSeasonNumber` | Номер следующего. Пусто — продолжения не ждём: сериал закончен или новый сезон не объявлен |
| `nextSeasonDate` | Когда ждём. Пусто при заполненном номере — **дата неизвестна** |

Правила целостности, их проверяет валидатор до записи:

- `seasonsReleased` — целое не меньше единицы;
- `nextSeasonNumber`, если задан, равен `seasonsReleased + 1`: ждать можно только следующий по счёту сезон;
- `nextSeasonDate` без `nextSeasonNumber` — ошибка данных;
- любое из трёх полей у тайтла без тега `series` — ошибка данных.

### Дата выхода — это дата мирового проката

**Датой выхода считается начало проката, а не первый публичный показ.** Фестивальная премьера, спецпоказ, показ для прессы, закрытая демонстрация на конвенте — не выход: тайтл в это время увидеть нельзя, а база — дневник зрителя, и её «вышел» обязано означать «доступен».

Берётся **самая ранняя дата коммерческого проката в мире**, в какой бы стране он ни начался: у «Закулисья реальности» это 28 мая 2026 года (Австралия), хотя в базе стояло 7 мая — день спецпоказа в Санта-Монике. Российская дата в это поле не идёт: почти ничего из базы до российского проката не доходит, и поле осталось бы пустым у большинства тайтлов.

Правило решено владельцем базы 24 августа 2026 года, после того как расхождение нашла зона критики на десятом заходе. Дата, взятая из первой попавшейся справки, регулярно оказывается премьерной — сверять надо по прокатному календарю.

**У фильма эпохи роудшоу дата выхода — начало роудшоу, а не общенациональный прокат.** Дополнение от 31.08.2026, при заведении «Унесённых ветром». До сороковых годов крупный фильм выпускали в два приёма: сначала роудшоу — платные сеансы по повышенным ценам в считаных городах, — и лишь через год-полтора общенациональный прокат по обычным ценам. У «Унесённых ветром» это 15 декабря 1939 года и 17 января 1941-го. Правило выше отвергает премьеру, потому что тайтл в это время увидеть нельзя; роудшоу этому не противоречит — билет продавался всем желающим, то есть фильм был доступен. Поэтому в `releaseDate` идёт начало роудшоу. Проверка та же, что и всегда: спрашиваем не «как это называлось», а «мог ли зритель купить билет».

**У сериала дата выхода — начало регулярного показа, а не ранняя выкладка пилота.** Приём, когда первую серию отдают публике за недели до старта сезона, у платформ обычный: Syfy выложил пилот «Пространства» 23 ноября 2015 года на VOD, iTunes, Hulu и YouTube — бесплатно и всем желающим, — а сезон пошёл 14 декабря двумя эпизодами и дальше по вторникам. Соблазн взять раннюю дату велик: посмотреть-то было можно, и правило про доступность как будто её и требует. Но доступна была одна серия из десяти, после чего наступила трёхнедельная пауза, и Variety называет это прямо — «early release strategy», то есть промо, а не начало проката. **В `releaseDate` идёт день, с которого сериал начали показывать подряд.** Решено владельцем 26 августа 2026 года при заведении «Пространства»; разбор — в `research/new-titles/the-expanse.md`.

**Расписание, восстановленное арифметикой, — не источник.** Аннотация «Одной из многих» называла финал первого сезона 26 декабря 2025 года, и это подтверждалось идеально: премьера 7 ноября с двумя эпизодами, дальше семь пятниц подряд, девять серий, и 26 декабря 2025 года — действительно пятница. Расчёт был верен, а дата неверна: за неделю до конца финал сдвинули на 23 декабря, чтобы не совпасть с премьерой другого сериала. **Календарь объясняет, откуда взялась дата, и ничего не говорит о том, действовала ли она.** Проверять надо по источнику; арифметика годится только на то, чтобы заметить, что дата подозрительна.

Дата допускает точность до месяца: анонс обычно называет месяц или премьерную пору, а не день. Точную дату записываем, когда она известна; **объявленный сезон без даты — нормальное состояние**, а не пробел: такой сериал встаёт в таймлайне в секцию «Дата выхода неизвестна».

**Статус продления подтверждается источником пояса A** — Variety, THR, Deadline, Screen Daily, IndieWire или официальным анонсом платформы. Ни агрегатор, ни Википедия, ни фанатское обсуждение здесь не годятся: слухи о продлении живут своей жизнью и опережают решение студии на месяцы. Не нашли подтверждения — оставляем номер пустым; это честнее, чем поставить сезон, которого не будет.

**Сезоны, как и теги, пишутся в два файла** — `films-data.json` и `content/seasons-data.json`.

### Когда сезон становится отдельным тайтлом

Вопрос решается не тем, сериал перед нами или фильм, а тем, **самостоятельная ли это вещь**. Проверка простая: есть ли у сезона собственное имя, собственная витрина и собственная история, которую можно посмотреть, не видев прочих.

**Отдельная карточка** — у антологии, где каждый сезон рассказывает свою историю со своим названием и своим составом («Американская история ужасов», «Фарго», «Настоящий детектив»), и у продолжения, поданного как самостоятельное произведение: «Киберпанк: Бегущие по краю 2» стоит в базе отдельным тайтлом со своей датой и своим досье, потому что мир подаёт его именно так.

**Одна карточка** — у связной истории, где сезон продолжает предыдущий: «Извне», «Чужой: Земля». Четыре сезона «Извне» четырьмя плитками превратили бы сетку из карты вкуса в список серий, справка задублировалась бы вчетверо и разошлась на первом же обновлении, а понятие «посмотрел сериал» просто исчезло бы.

**У связного сериала оценка одна на весь тайтл**, хотя сезоны и бывают разного качества. Это осознанный компромисс: дробить личные поля по сезонам значит заводить им отдельную таблицу и правило, как из сезонов складывается статус, — а выигрыш не стоит этой сложности. Разбор при этом по сезонам разводится, потому что там дело не в удобстве, а в спойлерах: см. [DOSSIER-FORMAT.md](DOSSIER-FORMAT.md), раздел «Сериал: досье описывает вышедшие сезоны».

## Постер

Два размера на тайтл, у российских фильмов русский плакат, у зарубежных международный. Рецепт целиком — в [docs/posters.md](../docs/posters.md); повторять его здесь незачем.

Единственное, что стоит помнить отдельно: после скачивания оба файла проверяются командой `file` — скачанная страница с ошибкой выглядит на диске как картинка ровно до этой проверки.

## Как ложится в данные

```bash
npm run check-data     # файлы сходятся между собой
npm run add-films      # долить тайтлы, которых в базе ещё нет
npm run refresh-films  # перенести правки справочных полей уже занесённых
npm run tag-films      # проставить теги
npm run fill-seasons   # записать сезоны
```

Долив идемпотентен: дублем считается совпадение оригинального названия, повторный прогон ничего не задваивает.

**`add-films` заводит только новые тайтлы и полей существующих не трогает** — иначе повторный прогон затирал бы правки, сделанные руками. Поэтому дозаполненное поле уже занесённой карточки переносит `refresh-films`: без флага он показывает, что изменится, с `--go` записывает. Личных полей и материалов агента он не касается — перечень колонок задан явным списком в `src/lib/refresh.ts`.

## Журнал

Работа записывается в `research/new-titles/<slug>.md`: запросы, прочитанные адреса с указанием пояса, таблица фактов по форме из [VERIFICATION.md](VERIFICATION.md), раздел «что не нашлось». Журнал нужен затем же, зачем архив досье, — чтобы через полгода не искать заново то, что уже искали.
