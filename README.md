# Кино База

Персональная база фильмов одного зрителя. На главной — сетка постеров, за каждым постером карточка тайтла: справка о фильме и его создателях, личная оценка по десятибалльной шкале, звёздочка «фильм моего вкуса», отметки «посмотрел» и «хочу посмотреть», комментарий владельца. Рядом со справкой — материалы, которые собирает агент: блок «Зачем смотреть» для тех, кто ещё не видел фильм, разбор «После просмотра» для тех, кто уже посмотрел, и «Важные вещи о фильме» — семь ключей к картине, написанных так, чтобы их можно было прочесть за минуту.

Формы добавления фильма в интерфейсе нет и не будет. Базу наполняет агент по трём скиллам: `film-card` заводит справочную карточку, `film-dossier` собирает досье, `creator-dossier` пишет страницу создателя. Как агент ищет, как проверяет найденное, что законно публиковать и в какой форме всё это записывается — шесть файлов правил в [research/](research/). Через интерфейс правятся только личные поля владельца; справка и материалы едут в базу из файлов `content/*.json` скриптами наполнения.

Это отчуждаемая версия проекта: человек клонирует репозиторий, его агент разворачивает базу локально и потом на своём VPS. В `content/` лежат пять зарубежных фильмов для примера — «Одиссея» (2026) и «Из машины» (2015) с полным досье, «Социальная расплата» (2026) только с блоком «Зачем смотреть», «Оглянись» (2024) и «Оборотень» (2026) только со справкой. Демо лежат в базе наравне с остальными записями, без пометки «пример»; когда они надоедят, достаточно попросить агента их убрать.

## Быстрый старт

Нужен Node 20 или новее: `better-sqlite3` собирается из исходников под вашу машину.

```bash
npm install
cp .env.example .env.local
npm run seed            # заводит базу data/kinobaza.db и заносит пять тайтлов со справкой и тегами
npm run fill-dossiers   # докладывает к трём из них материалы агента
npm run dev
```

База открывается на `http://localhost:3000`. Отдельного шага с миграциями нет: схема накатывается при первом открытии базы. Теги едут вместе со справкой в `seed`, отдельная команда для них нужна только при последующих правках. Команды `fill-seasons` и `fill-people` в демо ничего не делают — сериалов и персоналий в нём нет; они понадобятся, когда агент заведёт первый сериал или первую страницу создателя.

Агенту: первый заход — по `.agents/skills/kinobase-setup/SKILL.md`, порядок описан в [AGENTS.md](AGENTS.md).

## Как это работает

Справочные данные и материалы агента живут в файлах `content/*.json` и попадают в SQLite скриптами наполнения. Файл — источник правды: правка прямо в базе молча откатится следующим прогоном `refresh-films` или `tag-films`, поэтому справочные поля через интерфейс не правятся нигде.

Личные поля — оценка, звёздочка, отметки и комментарий — устроены наоборот: они существуют только в базе, в файлы не выгружаются и скриптами наполнения не затрагиваются. Правятся они на карточке фильма, и правила при этом держит сервер: оценка означает просмотр, «посмотрел» и «хочу посмотреть» взаимоисключающи, невышедший фильм не оценивается.

Локально любой посетитель считается владельцем — требовать вход в собственную базу на `localhost` бессмысленно. Разделение гостя и владельца включается только в боевой сборке: владельца узнают по куке с `OWNER_TOKEN`, а саму дверь `/owner/login` закрывает Basic Auth на стороне nginx. Владелец может посмотреть на сайт глазами читателя — режим гостя переключается в подвале и запрет на правку в нём держит сервер, а не вёрстка. Подробности устройства — [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Наполнение агентом

| Скилл | Что делает |
|---|---|
| `film-card` | Заводит справочную карточку: названия, дата выхода, создатели, аннотация, идентификаторы IMDb, Кинопоиска и TMDB, постер, теги, сезоны сериала |
| `film-dossier` | Собирает материалы к фильму: «Зачем смотреть», «Важные вещи о фильме» и разбор «После просмотра» с таблицей фактов и списком источников |
| `creator-dossier` | Пишет страницу создателя: справка, творческий метод и разбор того, как метод сработал в отдельных работах |

Скиллы лежат в [.agents/skills/](.agents/skills/) и читают правила из [research/](research/): как ищем ([SOURCING.md](research/SOURCING.md)), как проверяем ([VERIFICATION.md](research/VERIFICATION.md)), что законно ([LEGAL.md](research/LEGAL.md)) и три формы записи — [карточка](research/CARD-FORMAT.md), [досье](research/DOSSIER-FORMAT.md), [страница создателя](research/CREATOR-FORMAT.md).

Отдельных поисковых сервисов не требуется: без ключей агент ищет и читает страницы встроенными инструментами. Ключи Exa, Tabstack и Parallel улучшают охват и глубину — Exa находит ссылки, Tabstack читает страницы чистым текстом, Parallel добирает недостающее с постраничными ссылками на источник. Ключи кладутся в `.env.local`, а какая ступень поиска доступна, записано в [research/SEARCH-PROFILE.md](research/SEARCH-PROFILE.md) — этот файл заполняет онбординг.

Тексты, которые видит читатель, проходят через редактора. Редактор — скилл `redaktura` Люды Сарычевой и Никиты Архипова, он живёт отдельно и ставится из своего репозитория: https://github.com/N1arko/redaktura-skills. Без него редакторский проход делается по разделу «Редактор — третий проход, а не стилист» в [research/VERIFICATION.md](research/VERIFICATION.md).

## Сколько это стоит

Замеры автора, сентябрь 2026, один тайтл.

| Операция | Модель | Время по часам | Токены |
|---|---|---|---|
| Справочная карточка | Sonnet | около 10 минут | не замерялось |
| Полное досье | Opus, несколько параллельных агентов | от 45 до 150 минут | 1,5–1,8 млн без проверочных проходов, плюс около 70 центов поиска Exa |
| Блок «Важные вещи о фильме» отдельно | Opus | около 9 минут | не замерялось |
| Страница создателя | Opus | не замерялась | не замерялось |

Время здесь стенное: досье собирают несколько агентов сразу, и час с четвертью на часах складывается из нескольких часов их работы. Без ключей поиска заход выходит дольше и уже по охвату — встроенным инструментам труднее добраться до интервью и профильной прессы, а часть источников приходится пропускать.

## Сервер

Сайт разворачивается на своём VPS: systemd держит службу, nginx отдаёт её наружу и закрывает паролем вход владельца. Выкатывает скрипт `./deploy.sh` — он гонит проверки, переносит код, собирает приложение на сервере и перезапускает службу; базу он не трогает, она живёт отдельно и остаётся источником правды. Шаблоны службы и конфигурации лежат в [ops/](ops/), порядок первой установки — в [docs/server.md](docs/server.md).

## Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | Запускает сайт для разработки на `localhost:3000` |
| `npm run build` | Собирает боевую сборку |
| `npm start` | Запускает собранное приложение |
| `npm run lint` | Линтер |
| `npm test` | Прогоняет тесты один раз |
| `npm run test:watch` | Тесты в режиме наблюдения |
| `npm run db:generate` | Генерирует миграцию Drizzle после правки схемы |
| `npm run seed` | Наполняет пустую базу тайтлами из `films-data.json`; на непустой останавливается |
| `npm run add-films` | Доливает новые тайтлы в непустую базу, не трогая уже занесённые |
| `npm run tag-films` | Переносит теги из `tags-data.json` в базу |
| `npm run fill-seasons` | Переносит сезоны сериалов из `seasons-data.json` |
| `npm run fill-dossiers` | Переносит материалы агента из `dossier-data.json` |
| `npm run fill-people` | Заводит персоналии из `people-data.json` и связывает их с фильмами |
| `npm run refresh-films` | Обновляет справочные поля занесённых тайтлов; без флага `--go` только показывает, что изменится |
| `npm run check-data` | Сухая проверка файлов наполнения: базу не открывает и ничего не чинит |
| `npm run check-db` | Ищет в живой базе состояния, которые правила запрещают |
| `npm run check-dossier` | Механическая проверка досье и справочных полей по общему файлу данных |
| `npm run check-dossier-one` | То же для одной записи досье в отдельном файле |
| `npm run keys-check` | Проверяет форму блока «Важные вещи о фильме»: семь пунктов, объём, лид |
| `npm run check-facts` | Считает и проверяет таблицы фактов в архивах заходов |
| `npm run run-stats` | Считает заход по архивам и записям досье: страницы, факты, объём текста, источники |
| `npm run archive-slugs` | Печатает соответствие «оригинальное название → имя папки архива» |

## Структура репозитория

| Путь | Что там |
|---|---|
| `src/` | Приложение: страницы, компоненты, схема базы и общие модули |
| `src/site.config.ts` | Единственный файл, который правится под владельца: название, адрес, имя и ссылка |
| `content/` | Файлы данных — тайтлы, теги, сезоны, досье, персоналии |
| `scripts/` | Скрипты наполнения и проверок |
| `drizzle/` | Миграции схемы |
| `research/` | Шесть файлов правил для агентских текстов и профиль поиска |
| `docs/` | Устройство проекта, сервер, постеры |
| `ops/` | Шаблоны службы systemd и конфигурации nginx |
| `public/posters/` | Постеры в двух размерах |
| `tests/` | Тесты |
| `.agents/skills/` | Скиллы наполнения и вспомогательные |
| `DESIGN.md` | Визуальный мир: палитра, типографика, сетка |
| `viewer-profile.md` | Зрительский профиль владельца, по нему пишется рубрика «Почему это может быть интересно мне» |
| `deploy.sh` | Выкатка на свой сервер |
| `.env.example`, `deploy.env.example` | Образцы локальных настроек и настроек выкатки |
