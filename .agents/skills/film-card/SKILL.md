# Справочная карточка тайтла

Скилл заводит справочную часть тайтла: как называется, когда вышел, кто сделал, о чём в двух абзацах, какими тегами описывается. Досье («Зачем смотреть» и «После просмотра») этот скилл не пишет — для него есть `film-dossier`.

Работа механическая: почти всё проверяется по двум независимым базам, и почти на всё есть однозначный ответ. Отсюда главное правило: **не нашли — оставляем пусто**. Пустое поле честно, догадка — нет.

Модель: Sonnet. Суждения здесь нет, нужна дотошность.

## Что читать перед началом

- [research/CARD-FORMAT.md](../../../research/CARD-FORMAT.md) — целиком: перечень полей, требования к аннотации, идентификаторы, теги, сезоны;
- [research/SOURCING.md](../../../research/SOURCING.md) — разделы «Язык и форма запроса», «Инструменты и порядок чтения» вместе с подразделом «Запасной путь чтения», «Три пояса источников» вместе с подразделом «Что добавляется под задачу», «Имена по-русски» и подраздел «Имя папки латиницей» из «Архива». Разделы, помеченные в оглавлении файла «только для досье», карточке не нужны;
- [docs/posters.md](../../../docs/posters.md) — рецепт постера;
- [research/VERIFICATION.md](../../../research/VERIFICATION.md) — разделы «Таблица фактов» и «Статусы»; остальное там помечено «только для досье»;
- [research/LEGAL.md](../../../research/LEGAL.md) — раздел «Пометки, которых требует местное право», **только если** в аннотации заходит тема или **цитируется** издание, требующие пометки по праву владельца базы. Справочная база как источник идентификаторов, рейтинга и аннотации под это условие не подпадает, иначе оно срабатывало бы на каждой карточке.

Правил в этом файле нет — они в перечисленных выше. Здесь маршрут.
**Ограничение на запись не ограничивает чтение.** Задача может запрещать трогать файлы за пределами одной папки — читать правила, словари и код это не запрещает никогда. Агент, не открывший словарь из-за такой оговорки, работает по памяти о правиле, а не по правилу.

## Шаг 1. Понять, чего нет

```bash
sqlite3 data/kinobaza.db "select id, title_ru, title_original, release_date, imdb_id, kinopoisk_id, director, composer, poster_path, tags, seasons_released from films where title_ru like '%<часть названия>%' or title_original like '%<часть названия>%';"
```

- Записи нет — заводим новую.
- Запись есть — дозаполняем только пустые поля и **не трогаем заполненные**. Исключение одно: поле явно устарело (вышел новый сезон, изменилась объявленная дата), и тогда правим его осознанно.
- Личные поля (`watched`, `want_to_watch`, `my_rating`, `taste_star`, `comment`) не трогаем никогда.

**Готово, когда** составлен список полей, которые предстоит заполнить.

## Шаг 2. Опознать тайтл

Одноимённых фильмов много, ремейков ещё больше. Сверять надо по году **и** режиссёру, а не по названию.

1. TMDB: `https://www.themoviedb.org/search?query=<название в urlencode>` → числовой идентификатор из ссылки вида `/movie/701387-bugonia`. В базу он не пишется, но нужен для постера.
2. IMDb: поисковая подсказка `https://v2.sg.media-imdb.com/suggestion/<первая буква>/<название>.json` → идентификатор вида `tt12300742`. Обычные страницы IMDb роботам не отдаются.
3. Кинопоиск: числовой идентификатор из адреса карточки. Часто отвечает капчей — тогда идентификатор берётся из выдачи поиска, а рейтинг остаётся пустым.

**Если однозначно опознать не удалось — остановиться и спросить владельца.** Не выбирать самому: неверный идентификатор уводит ссылку в карточке на чужой фильм, и заметить это трудно.

**Готово, когда** известны TMDB-идентификатор и, если существуют, идентификаторы IMDb и Кинопоиска.

## Шаг 3. Собрать поля

Идти по перечню из `CARD-FORMAT.md`, раздел «Поля». По каждому добытому факту — строка в таблицу фактов журнала (форма — в `VERIFICATION.md`).

Имена создателей — **кириллицей**. Есть устоявшееся русское написание — берём его; нет — транслитерируем по языку происхождения имени, а не по английскому чтению. Латиница в этих полях означает недоделанную запись.

Аннотация — по `CARD-FORMAT.md`, раздел «Аннотация»: там и длина, и источник, и перечень того, чего в ней быть не должно. Читать его надо, а не вспоминать.

`createdAt` — единственное поле, которое не ищется, а ставится; правило — в `CARD-FORMAT.md`, раздел «Дата заведения».

**Готово, когда** каждое поле из перечня либо заполнено, либо осознанно оставлено пустым.

## Шаг 4. Сериал — сезоны

Только если у тайтла тег `series`. Три поля: сколько сезонов вышло, номер следующего, дата следующего.

**Статус продления подтверждается источником пояса A** — какими именно и что не годится, сказано в `CARD-FORMAT.md`, раздел «Сезоны сериала».

Не нашли подтверждения — `nextSeasonNumber` остаётся пустым. Объявленный сезон без даты — нормальное состояние, дату не угадываем.

Правила целостности — в `CARD-FORMAT.md`, раздел «Сезоны сериала». Записывать **в оба файла**: `films-data.json` и `seasons-data.json`.

**Готово, когда** три поля заполнены или обоснованно пусты, и записи в двух файлах совпадают.

## Шаг 5. Постер

По рецепту из `docs/posters.md`: два размера, у российских фильмов русский плакат, у зарубежных международный.

После скачивания — обязательно:

```bash
file public/posters/<slug>.jpg           # "JPEG image data ... 780x1170"
file public/posters/original/<slug>.jpg  # "JPEG image data ...", ширина заметно больше 780
```

Скачанная страница с ошибкой выглядит на диске как картинка ровно до этой проверки.

**Готово, когда** обе команды показали JPEG нужного размера.

## Шаг 6. Теги

Словарь `src/lib/tags.ts` — источник правды: тег вне словаря записать нельзя, скрипт отвергнет весь файл. По одному тегу формы (`film` или `series`) и вида (`live-action`, `animation`, `documentary`) обязательно; дальше жанры и настроения — сколько есть по существу.

Записывать **в оба файла**: `films-data.json` и `tags-data.json`.

**Готово, когда** наборы тегов в двух файлах совпадают.

## Шаг 7. Записать и проверить

```bash
npm run check-data           # файлы данных сходятся между собой
npm run add-films            # новые тайтлы
npm run refresh-films        # покажет, что изменится у уже занесённых
npm run refresh-films -- --go   # и запишет
npm run tag-films
npm run fill-seasons
```

`check-data` красный — чинить файлы, а не обходить проверку.

**`add-films` заводит только новые тайтлы**: правку поля у карточки, которая уже в базе, переносит `refresh-films`. Без него файл и база разойдутся молча, и `check-data` этого не заметит — он сверяет файлы между собой. Править базу руками не надо ни при каких обстоятельствах.

**Готово, когда** `check-data` зелёный, все скрипты прошли с нулевым кодом, а повторный `npm run refresh-films` говорит, что переносить нечего.

## Шаг 8. Журнал

`research/new-titles/<slug>.md`: запросы, прочитанные адреса с указанием пояса, таблица фактов, раздел «что не нашлось». Форма журнала — в `CARD-FORMAT.md`, раздел «Журнал».

## Чего этот скилл не делает

Не пишет досье и разбор — это `film-dossier`. Не заводит персоналию — это `creator-dossier`. Не проставляет личные поля: отметки «Посмотрел» и «Хочу посмотреть», оценку, звёздочку и комментарий ставит только владелец.
